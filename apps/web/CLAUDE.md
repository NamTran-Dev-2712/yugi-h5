# apps/web

Phaser 3 + Vite 7. Client chỉ vẽ những gì server nói qua GameEvent — không tự suy luận
luật chơi, không tự đổi game state.

Luật riêng:

- Import được: `@yugi/shared` (types/constants/card definitions). KHÔNG import
  `@yugi/game-engine` trực tiếp trừ khi export rõ ràng là type/utility thuần (không phải
  `applyAction`/rule logic) — engine chạy ở server, client không được tự chạy rule.
- `state/` (Zustand) chỉ là view state phản chiếu server, không phải nguồn sự thật.
- Animation/hiệu ứng bind vào `GameEvent` nhận từ server (xem `docs/design/protocol.md`),
  không viết logic "nếu tôi kéo lá bài thì..." ở client trước khi server xác nhận.
- Input (drag-drop) chỉ tạo "Action intent" gửi lên server; UI cập nhật khi có event trả về.
- `src/api/` (client HTTP `createDuelApi`, tiêm `fetch`/`storage`, lỗi = `DuelApiError` có `status`/`code`/`engineCode`) là lớp mạng dùng chung cho Phaser và trang debug; type response lấy từ `@yugi/shared` (`http-types`). Action gửi đi là `PlayerAction` của shared, build xong qua `PlayerActionSchema.parse`.
- `src/debug/` + `debug.html` (task 2.4) là công cụ tạm kiểm luật, KHÔNG Phaser, dễ xoá (xoá thư mục + `debug.html` + khoá `debug` ở `vite.config.ts`). Logic thuần (`describe-event`, `build-actions`, `debug-state`) có test; `debug-page.ts` chỉ là DOM. Nút chỉ liệt kê những gì đang có trên màn hình, KHÔNG sao chép luật (Level→tribute, phase, lượt); từ task 2.5 `applyLegality` đối chiếu với `legalActions` của server để làm mờ/tắt nút và thu hẹp ô chọn (công tắc "Cho phép thử hành động sai luật" tắt việc này để thấy 409 + `engineCode`); UI giữ nguyên state khi bị từ chối. Phaser sau này dùng `legalActions` để highlight ô hợp lệ, không tự suy luận. Thêm loại action mới = thêm nhánh ở `build-actions.ts` + thêm loại `EventView` = `describe-event.ts` (compile-time vét cạn).
- Trang debug có mode "Đấu với AI" (task 2.6): viewer khoá ở ghế người (server trả 403 nếu xem ghế AI), không dựng nút cho ghế AI, không tự chuyển viewer; `aiActions` trong response (cắt lát `events`) được ghi thành dòng "🤖 AI …" trước các event của nó (`describe-ai-action.ts`, vét cạn `never`; `logLinesFor` ở `debug-state.ts`). Web KHÔNG biết AI chọn thế nào — chỉ hiển thị điều server đã làm.
- Duel Scene Phaser (task 2.7) — `src/duel/` là lớp THUẦN (không import `phaser`, có test): `layout.ts` (hình học), `presenter.ts` (`StateView`+`legalActions` → `RenderModel`), `duel-controller.ts` (nối `DuelApi`), `theme.ts` (mọi màu/font/kích thước — đổi phong cách ở đây), `asset-manifest.ts` (key texture ổn định), `strings.ts` (chuỗi UI, chờ i18n 2.12). `src/scenes/` chỉ vẽ `RenderModel` (không quyết luật, không dựng payload action: nút/lá gửi đúng action server liệt kê trong `legalActions`). Presenter không được đưa `definitionId`/tên lá ẩn vào model (có test quét JSON + mutant). Placeholder texture sinh bằng code ở Boot theo manifest, không dùng art Konami. Fixture xem không cần server: `index.html?fixture=midgame|handfull|gameover` — chỉ DEV (`import.meta.env.DEV`, dữ liệu ở `fixtures.ts` import động; tên ở `fixture-names.ts`). Thêm loại action UI mới = thêm nhánh ở presenter/controller + test; đổi khung/kích thước = `theme.ts`.
- Tương tác kéo thả (task 2.8), cũng THUẦN trong `src/duel/`: `legal-index.ts` (chỉ lọc/nhóm `legalActions`: ô hợp lệ, tribute, mục tiêu, đổi thế; `sameAction`/`isListed` so cấu trúc), `interaction.ts` (máy trạng thái `idle → dragging-card|dragging-attack → choosing-option → selecting-tribute → pending-server`; `reduce` trả `send`/`toast`; **mọi action gửi phải là phần tử của `legalActions`**, không có logic luật ở client, không optimistic), `interaction-driver.ts` (nối máy với `DuelController`), hit-test ở `layout.ts` (`hitTest`, `zoneIndexAt`, `optionRects`), `error-messages.ts` (mã lỗi server → câu tiếng Việt; thêm mã engine mà quên câu = test đỏ). Scene (`duel-scene.ts`) chỉ chuyển Phaser pointer events (chuột + cảm ứng) cho driver và vẽ `OverlayModel`. Thêm loại action UI mới = bộ lọc ở `legal-index.ts` + nhánh ở `interaction.ts` + test (đỏ trước) + mutant. `controller.submit` từ chối action không được liệt kê; fixture (`?fixture=…`, gồm `summon-choice|tribute|attack|attack-direct|drag-illegal`) "gửi" chỉ ghi log `sẽ gửi: …`. Lá thuộc đối thủ chỉ được nhận diện theo vị trí/`instanceId`, không tên. Không dùng `SMP-011..013` trong fixture (test rò rỉ dùng chúng làm lá "bí mật").
- Animation theo event (task 2.9), THUẦN trong `src/duel/`: `animation-queue.ts` (`stepsFor`/`segmentsFor`: `EventView[]` + `aiActions` → `AnimationSegment[]`, vét cạn `never`, `DURATION_MS` là bảng thời lượng duy nhất), `animation-player.ts` (phát tuần tự, scheduler tiêm được → test bằng fake timers; `skip`, `setSpeed`, `animationSpeedFromSearch`, `AnimatorHost`). `duel-controller.ts` nhận `animator?`: board giữ view CŨ + `animating`/`busy` true trong lúc phát, xong mới snap `response.view` (log vẫn ghi ngay). Khoá input dùng `busy`, KHÔNG có kind riêng ở `interaction.ts`. Scene (`playStep`) chỉ vẽ hiệu ứng tạm vào container `fx` từ field của step; Space/Enter = skip; `?fast=1`, `?anim=off`. Thêm `EventView` mới = `stepFor` đỏ `tsc` + test. e2e/fixture không truyền animator ⇒ không animate.
- Log panel (task 2.10), THUẦN trong `src/duel/`: `duel-controller.ts` giữ `log: string[]` (trang debug/e2e dùng) VÀ `entries: LogEntry[]` song song (cùng nội dung, cùng trần 200; `addLog` nhận entry). `log-entries.ts` gắn nhóm `field|combat|turn|error` theo `EventView['type']`/`PlayerAction['type']` (vét cạn `never`, KHÔNG đoán từ text; `entriesFor` phải khớp `logLinesFor`), `log-panel.ts` = trạng thái ẩn/hiện + lọc, hit-test chip/nút, localStorage `yugi.logPanel` (try/catch). Scene kiểm `logHitTest` trước driver ở `pointerdown`; phím L bật/tắt. Thêm loại event/action = thêm nhánh nhóm. `tools/ui-log-shots.ts` chụp panel (API + dev server + Edge).
- Duel Sandbox (task 2.11, DEV): `dev/sandbox.html` + `src/dev/` (`sandbox-load.ts` THUẦN: parse JSON + `ScenarioSchema` → lỗi tiếng Việt, `sampleList`; `sandbox-page.ts` chỉ DOM; `sandbox-scenes.ts` 2 scene nhỏ quanh `DuelScene` THẬT — không sửa `DuelScene`/interaction/animation/log). Nạp = `controller.startScenario` → `api.createSandbox` (`POST /dev/sandbox/duels`); web không dựng state, không kiểm id lá (server làm). Trang KHÔNG có trong `rollupOptions.input` (không lên production; đừng thêm). Scenario mẫu ở `packages/shared/scenarios/*.json` (nạp bằng `import.meta.glob ?raw`). `tools/ui-sandbox-shots.ts` chụp trang thật (API + dev server + Edge).
- Test mạng thật (không trình duyệt): `node --experimental-strip-types tools/play-duel-ui.ts [bộ lọc]` chạy `src/e2e/*.e2e.ts` bằng vitest (`vitest.e2e.config.ts`, cần API + Postgres, không nằm trong `pnpm test`); `tools/ui-drag-shots.ts` điều khiển Edge headless bằng chuột thật để chụp từng bước kéo thả (cần dev server `:5173`).
- Dùng `textContent`, không `innerHTML` với dữ liệu từ server.
