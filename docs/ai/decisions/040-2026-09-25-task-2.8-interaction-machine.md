## 2026-09-25 — Máy trạng thái tương tác (task 2.8): thuần, luôn khớp `legalActions`, không optimistic

- **Máy trạng thái thuần** `apps/web/src/duel/interaction.ts` (`reduce(state, event, ctx) → {state, effects}`; không Phaser/I/O/đồng hồ): `idle → dragging-card | dragging-attack → choosing-option → selecting-tribute → pending-server → idle`. Effect chỉ có `send(action)` và `toast(text)`. Test được bằng dữ liệu thuần + toạ độ layout; scene chỉ chuyển pointer events và vẽ overlay. `interaction-driver.ts` (cũng thuần) nối máy với `DuelController`.
- **Luôn khớp `legalActions`**: client không dựng action, không có logic luật. `legal-index.ts` chỉ lọc/nhóm danh sách server gửi (ô hợp lệ của lá tay, tập tribute, mục tiêu tấn công, đổi thế, đáp án prompt); mọi action gửi đi là phần tử của danh sách (`emit` kiểm lại bằng so sánh cấu trúc `sameAction`, độc lập thứ tự khoá — thay `JSON.stringify` cũ ở controller). Xác nhận tribute/bỏ bài chỉ bật khi tập chọn **khớp đúng một action liệt kê** (theo ô đã thả), nên "đủ/thiếu/thừa" do server quyết, client không đếm Level. Tribute vào ô đang có quái chỉ khi server liệt kê (luật ô giải phóng 1.4).
- **Không optimistic**: board chỉ đổi khi server trả state. `pending-server` hoặc controller `busy` (AI đang đi) bỏ qua mọi input; server từ chối (409/403…) → `serverRejected` → về idle + toast, `view`/`legalActions` giữ nguyên tham chiếu (lá "về chỗ cũ" chỉ là không có gì đổi). Controller mới: `submit` trả `SubmitResult`; không liệt kê thì từ chối tại chỗ, không tới server; fixture (không API/duelId) chỉ ghi log "sẽ gửi: …".
- **Hit-test thuần ở `layout.ts`** (`pointInRect` nửa mở, `zoneIndexAt`, `optionRects`, `hitTest`: lá trên cùng theo thứ tự vẽ → LP → nút). Chuột và cảm ứng dùng chung Phaser pointer events, không listener riêng theo object (trừ hover chi tiết).
